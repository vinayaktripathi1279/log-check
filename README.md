## 🔍 Project Overview

In production Linux environments, SSH servers record every authentication attempt to `/var/log/auth.log` (or `/var/log/secure`). Security Operations Center (SOC) analysts and Security Information & Event Management (SIEM) systems continuously monitor these logs to detect unauthorized access attempts.

This project implements that core detection pipeline from scratch using only Python's built-in libraries:
1. **Log Ingestion & Parsing**: Extracts timestamps, target usernames, and source IPs using Regular Expressions (`re`).
2. **Velocity-Based Anomaly Detection**: Evaluates whether an IP address exceeded **5 failed login attempts within any 5-minute sliding window**.
3. **Severity Rating**: Tiers the alert level into **Medium**, **High**, or **Critical**.
4. **Triage Reporting**: Generates a standard `report.csv` file for automated ticketing or SIEM forwarding, and prints an executive summary table to the terminal.

## 📖 Step 3: Code Walkthrough & Reading Order

Read the files in the following order to understand how every component works:

### 1. Understanding Synthetic Log Generation (`generate_logs.py`)
Open [`generate_logs.py`](generate_logs.py). Real SSH failure lines look like:
```text
Sep 27 17:15:04 secure-srv01 sshd[14205]: Failed password for root from 203.0.113.45 port 42102 ssh2
Sep 27 17:15:09 secure-srv01 sshd[14206]: Failed password for invalid user admin from 203.0.113.45 port 42103 ssh2
```
In `generate_logs.py`, observe:
- `generate_brute_force_events()` generates bursts of failures spaced only **3 to 10 seconds** apart, simulating an automated password spraying tool like Hydra or Medusa.
- `generate_normal_events()` creates benign logins spaced minutes apart and simulates occasional user typos (1 failed login immediately followed by a successful login).
- All events are combined and sorted chronologically so the log simulates a real 24-hour timeline.

### 2. Regex Parsing (`analyzer.py`)
In [`analyzer.py`](analyzer.py#L38-L48), look at `SSH_FAILED_REGEX`:
```python
SSH_FAILED_REGEX = re.compile(
    r"^([A-Z][a-z]{2}\s+\d+\s+\d{2}:\d{2}:\d{2})\s+\S+\s+sshd\[\d+\]:\s+"
    r"Failed password for\s+(?:invalid user\s+)?(\S+)\s+from\s+([0-9]{1,3}(?:\.[0-9]{1,3}){3})"
)
```

**Regex Breakdown Table:**
| Token | What It Matches | Example |
| :--- | :--- | :--- |
| `^([A-Z][a-z]{2}\s+\d+\s+\d{2}:\d{2}:\d{2})` | Captures Group 1: Month, day, and time | `Sep 27 17:15:04` |
| `\s+\S+\s+sshd\[\d+\]:\s+` | Hostname and SSH process PID | `secure-srv01 sshd[14205]:` |
| `Failed password for\s+` | The failure indicator | `Failed password for ` |
| `(?:invalid user\s+)?` | Optional non-capturing group for invalid account scans | `invalid user ` (if present) |
| `(\S+)\s+` | Captures Group 2: Target username | `root` or `admin` |
| `from\s+` | Keyword preceding IP | `from ` |
| `([0-9]{1,3}(?:\.[0-9]{1,3}){3})` | Captures Group 3: Source IPv4 address | `203.0.113.45` |

### 3. The 5-in-5-Minutes Detection Rule
In [`analyzer.py`](analyzer.py#L98-L130), look at `detect_brute_force()`:
```python
def detect_brute_force(timestamps: list, window_minutes: int = 5) -> int:
    max_failures_in_window = 0
    window_duration = timedelta(minutes=window_minutes)

    for i in range(len(timestamps)):
        current_time = timestamps[i]
        window_end = current_time + window_duration

        # Count failures that occurred within this 5-minute window
        burst_count = sum(1 for t in timestamps[i:] if t <= window_end)

        if burst_count > max_failures_in_window:
            max_failures_in_window = burst_count

    return max_failures_in_window
```
**Why plain total count is not enough:**
If a remote employee mistypes their password once on Monday, once on Wednesday, and three times on Friday, their total failures equal 5 over five days. That is **benign human error**.
However, if an IP generates 5 failures in 30 seconds, that is **automated brute force**. The sliding window checks the *velocity* of failures.

### 4. Severity Rating Function
In [`analyzer.py`](analyzer.py#L133-L148), look at `calculate_severity()`:
```python
def calculate_severity(failure_count: int) -> str:
    if failure_count >= 20:
        return "Critical"
    elif failure_count >= 10:
        return "High"
    elif failure_count >= 5:
        return "Medium"
    else:
        return "Low"
```
Simple, predictable thresholding that can easily be adjusted or integrated into an automated firewall or SIEM rule.

### 5. CSV Report Generation
In [`analyzer.py`](analyzer.py#L151-L172), `write_csv_report()` uses Python's standard `csv.DictWriter` to export structured columns (`IP`, `failed attempts`, `first seen`, `last seen`, `severity`) without needing third-party libraries like Pandas.

## 🧠 Cybersecurity Fundamentals to Master

When talking to hiring managers and interviewers, be prepared to discuss these core concepts:

1. **Brute-Force & Credential Stuffing**:
   - **Brute Force:** Trying thousands of passwords against a known username (e.g. `root`).
   - **Password Spraying:** Trying one common password (e.g., `Spring2026!`) across hundreds of different accounts to avoid lockouts.
   - **Why repeated failures matter:** Repeated failures within short windows indicate an automated script rather than human input.

2. **Log Monitoring & SIEM**:
   - This script demonstrates the exact logic used by enterprise SIEMs (like Splunk, Microsoft Sentinel, or Elastic Security) and host intrusion prevention systems (HIPS) like **Fail2ban**.
   - Fail2ban parses `/var/log/auth.log` with regex and automatically writes an `iptables` or `nftables` firewall rule to block the offending IP address.

3. **Detection Thresholds & Tuning (False Positives vs. False Negatives)**:
   - **Threshold too low (e.g. 2 failures in 10 minutes):** High **False Positive** rate. Legitimate users get locked out and SOC analysts suffer alert fatigue.
   - **Threshold too high (e.g. 100 failures in 5 minutes):** High **False Negative** rate. Attackers running slower, stealthy dictionary attacks fly under the radar.
